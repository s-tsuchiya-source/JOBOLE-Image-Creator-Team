# Local Image AI Setup for First Test

初回テストでは `IMAGE_BACKEND=local_webui` を使用し、画像生成APIの従量課金なしで1枚のE2Eテストを行う。

本リポジトリ側はAUTOMATIC1111 / SD-WebUI-Forge互換REST APIへ接続する。

## 0. 先にGPUを確認

リポジトリで:

```powershell
python scripts/check_local_gpu.py
```

NVIDIA GPUがある場合、GPU名とVRAMが表示される。

ローカル画像AIのモデル選定はVRAMに依存するため、最初にこの結果を確認する。

## 1. AUTOMATIC1111を使う場合

公式リポジトリ:

https://github.com/AUTOMATIC1111/stable-diffusion-webui

Windows 10/11 + NVIDIA GPUでは、公式README/WikiのWindows手順に従って導入する。

代表的な方法は以下。

1. Python 3.10系をWebUI用に用意する。
2. Gitを用意する。
3. 任意の画像AI用フォルダへcloneする。

```powershell
git clone https://github.com/AUTOMATIC1111/stable-diffusion-webui.git
```

JOBOLEリポジトリがPython 3.13でも問題ない。Stable Diffusion WebUIは自分のフォルダ内に独立したvenvを作成するため、JOBOLE側Pythonと分離して運用する。

## 2. REST APIを有効にする

`stable-diffusion-webui/webui-user.bat` を開き、`COMMANDLINE_ARGS` に `--api` を追加する。

例:

```bat
set COMMANDLINE_ARGS=--api
```

低VRAM用の起動引数等が必要な場合は、GPUに合わせて同じ行へ追加する。

その後 `webui-user.bat` を起動する。

正常なら通常:

```text
Running on local URL: http://127.0.0.1:7860
```

となる。

APIドキュメント確認:

```text
http://127.0.0.1:7860/docs
```

本システムが利用する主なendpoint:

```text
GET  /sdapi/v1/options
GET  /sdapi/v1/sd-models
POST /sdapi/v1/txt2img
```

## 3. checkpoint

WebUIで実際に画像生成できるcheckpointを1つロードする。

本システムはローカルモデルをGitHubへ固定しない。理由:
- GPU VRAMによって適切なモデルが違う
- モデルライセンスを案件用途に合わせて確認する必要がある
- 後から高品質モデルへ差し替えられるようにするため

最初の接続確認では、WebUI上で1枚生成できる状態になっていればよい。

## 4. JOBOLE `.env`

```env
IMAGE_BACKEND=local_webui
LOCAL_IMAGE_API_URL=http://127.0.0.1:7860
LOCAL_IMAGE_MODEL=local-loaded-checkpoint
LOCAL_IMAGE_STEPS=28
LOCAL_IMAGE_CFG_SCALE=6.5
LOCAL_IMAGE_SAMPLER=DPM++ 2M
LOCAL_IMAGE_TIMEOUT_SEC=600
```

`LOCAL_IMAGE_MODEL` は現時点ではログ・記録用ラベル。実際に使用するcheckpointはWebUIでロードされているモデル。

## 5. 接続確認

WebUIを起動した状態で:

```powershell
python scripts/check_local_image.py
```

期待値:

```text
IMAGE BACKEND: PASS
backend: local_webui
ok: True
base_url: http://127.0.0.1:7860
current_model: ...
incremental_cost_yen: 0.0
No image was generated by this check.
```

または:

```powershell
python scripts/validate_system.py --verify-image
```

## 6. 実画像を1枚だけ単独テスト

制作パイプライン全体を回す前に、ローカルAI単体で512x512を1枚作れることを確認できる。

```powershell
python scripts/test_local_image_generation.py
```

成功:

```text
LOCAL IMAGE GENERATION: PASS
Output: ...\tmp\local-image-test.png
Incremental cloud image API cost: 0 JPY
```

このテストはOpenAI画像APIを呼ばない。

## 7. Claude / Codexも確認

```powershell
python scripts/validate_system.py --runtime-config
python scripts/validate_system.py --verify-login
```

`--verify-login` はClaude/ChatGPTの契約利用枠を少量使うが、テキストAPIキーは使用しない。

## 8. 初回1枚E2Eテスト

求人原稿が入っている制作枚数1の案件で:

```powershell
python scripts/run_production.py PJ-XXXX --dry-run
```

PASSしたら:

```powershell
python scripts/run_production.py PJ-XXXX
```

このテストの画像バックエンドはローカルPCなので、画像APIの従量課金は0円。

ただし以下は消費する。
- PCのGPU計算時間
- 電力
- Claude Codeの契約利用枠
- Codex/ChatGPTの契約利用枠

## 9. ローカル品質が不十分な場合

AIチーム全体は変更しない。

`.env` の画像バックエンドだけ本番用へ切り替える。

```env
IMAGE_BACKEND=openai
```

これによりRecruitment / Strategy / Copy / Art / Prompt / Reviewer / Codex Quality Gateの設計はそのまま維持し、画像レンダラーだけOpenAIへ変更できる。

## 10. セキュリティ

初回テストではローカルPCからだけアクセスするため、`--listen` や `--share` は不要。

`127.0.0.1:7860` のまま使用し、インターネットへWebUI APIを公開しない。
